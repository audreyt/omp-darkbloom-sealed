✣sealed between rooms密封穿梭兩室
·

A coding assistant may receive unfinished code, stubborn error messages, private filenames, or a secret left in a config file. The chat feels like one conversation. Behind it, your words cross several machines.程式助理收到的，可能是未完成的程式碼、難解的錯誤訊息、私密檔名，或留在設定檔裡的密鑰。眼前看來只是一場對話，背後的文字卻會穿過好幾台機器。

A small distinction with a large consequence一個細微、卻重要的分別

Code can open your prompt.
No person along the way can see it.程式碼可以打開提示詞，
沿途卻沒有人能看得到。

omp is an open-source coding assistant that can use different AI services. This add-on carries the request body past the internet’s front desk in a sealed envelope. Later, only protected software on two locked-down machines opens it briefly; Darkbloom staff and machine owners cannot see it.omp 是一個開源程式助理，可以選用不同的 AI 服務。這個外掛讓請求內容以密封信封通過網路「櫃檯」。之後，只有兩台受保護機器裡的程式碼會短暫解封；Darkbloom 人員和機器擁有者都看不到內容。

What “no person can see” means「沒有人看得到」究竟是什麼意思

Two machines do the work.
Every person stays outside.工作交給兩台機器，
內容卻沒有人能看得到。

The first protected machine opens the envelope just long enough for software to choose a model and record the cost. Staff cannot watch, log, or keep what it says. The software seals it again for one model Mac. There, the verified Darkbloom app opens it only while the model works; the Mac owner cannot look inside. The answer is sealed before it leaves.第一台受保護的機器只讓程式碼短暫拆信，以選擇模型並記錄用量；工作人員無法查看、記錄或保留內容。程式碼隨即把信重新封給一台模型 Mac。到了那裡，通過驗證的 Darkbloom 應用程式只在模型運算時解封，Mac 擁有者無法看到；回答離開前也會先封好。

For a few moments, software handles readable words inside protected memory. People do not. Everywhere between machines, the prompt is sealed.短短幾刻，程式碼在受保護的記憶體裡處理可讀內容；沒有人能看得到。機器與機器之間，提示詞始終密封。

One named destination指定一個確切終點

You can choose the exact Mac that does the work.你可以指定：就由這一台 Mac 完成工作。

Before Darkbloom sends a private prompt to any model Mac, it checks that the machine is genuine, its protections are intact, and the real Darkbloom app is running. If you contribute a Mac of your own, you may name that exact machine—and allow no substitute. Its owner still cannot see inside the protected app.Darkbloom 在把私密提示詞交給任何模型 Mac 之前，會先確認機器是真的、保護功能完整，而且正在執行正版應用程式。若你提供自己的 Mac，還可以指定就由這一台完成工作，不准換成其他機器。即使如此，Mac 擁有者仍看不到受保護應用程式裡的內容。

The promise is not that software never opens the prompt—the model could not help if it did not. The promise is that software uses readable words only inside two protected machines while every person stays out. The prompt arrives sealed, leaves sealed, is never logged or kept, and cannot be seen by the people operating the route.這項承諾，不是程式碼永遠不打開提示詞——若真如此，模型也無法幫忙。承諾在於：可讀內容只在兩台受保護的機器裡交給程式碼處理，任何人都在外面，誰也看不到。提示詞密封抵達、密封離開，不寫入日誌，也不在工作結束後保留。

For the curious: exact protocol and evidence想知道技術細節：協定與證據的完整說明

What stays sealed in transit傳輸途中密封哪些內容

Standard TLS protects the trip to a reverse-proxy front desk, where TLS ordinarily ends. This add-on goes further: every POST body is NaCl Box sealed before that desk, with a fresh ephemeral X25519 keypair for each request. Between every machine and every hop, the prompt is ciphertext. Successful buffered and SSE responses return as encrypted chunks through omp’s native tool-call path. GET model discovery is unsealed because it carries no prompt body.標準 TLS 會保護前往反向代理「櫃檯」的路程，而 TLS 通常在那裡終止。這個外掛再多走一步：每筆 POST 內容都在抵達櫃檯前，以每次請求新建的臨時 X25519 金鑰組透過 NaCl Box 密封。提示詞在每台機器、每一段路之間都是密文。成功的整批回應與 SSE 回應都以加密片段，經 omp 原生工具呼叫流程返回。GET 模型探索不帶提示詞內容，因此不密封。

Where protected code opens it受保護的程式碼在哪裡解封

Darkbloom’s coordinator opens the request transiently only inside Confidential VM memory so code can route and bill it, then NaCl-seals it anew to the selected provider’s attested X25519 key. The provider opens it only inside the genuine hardened Darkbloom app to run the model, then seals response chunks back. “Opened by protected code” does not mean “exposed to a person”: staff, provider owners, and operators have no prompt view.Darkbloom 協調器只會在機密虛擬機的記憶體裡短暫解封，讓程式碼完成路由與計費，隨即以 NaCl 重新密封給獲選供應端通過證明的 X25519 金鑰。供應端只會在正版、強化過的 Darkbloom 應用程式內解封以執行模型，再把回答逐段封回。「由受保護的程式碼解封」不等於「攤給人看」：Darkbloom 人員、供應端擁有者與操作人員都看不到提示詞。

What the boundary forbids這道界線禁止什麼

Prompt content is never logged, exposed to observability, forwarded to an outside service, or retained after the request. It may not be handed to a subprocess or interpreter that escapes the protected runtime. Private routing requires encrypted response chunks, a registered key, verified SIP, Secure Boot and runtime state, hardware or Secure Enclave attestation, and genuine-app code identity.提示詞內容不得寫入日誌、出現在監測系統、轉送到外部服務，也不得在請求結束後保留；更不能交給會逃出受保護執行環境的子程序或直譯器。私密路由要求回答逐段加密、金鑰已登記、SIP、Secure Boot 與執行狀態通過驗證、硬體或 Secure Enclave 證明有效，且程式碼身分確屬正版應用程式。

Pinning and failure釘選與關閉失敗

Optional hard pinning selects one exact owned Mac and key; it does not give that Mac’s owner a view. Missing keys, tampering, plaintext successful POST responses, failed platform or code-identity checks, and hard-pin mismatches all fail closed. There is no plaintext fallback and no quiet rerouting to an unverified provider.可選的硬釘選會指定一台你擁有的 Mac 與一把確切金鑰，卻不會讓 Mac 擁有者看到內容。金鑰缺失、內容遭竄改、POST 成功回應卻是明文、平台或程式身分檢查失敗，以及硬釘選不符時，都會關閉失敗；沒有明文備援，也不會悄悄改送未驗證的供應端。
